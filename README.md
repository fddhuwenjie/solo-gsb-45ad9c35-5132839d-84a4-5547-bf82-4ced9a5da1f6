# 🔭 天文观测窗口规划台

输入观测点经纬度、UTC 日期范围和带赤经/赤纬/曝光时长/优先级的观测目标，
系统按球面天文公式**逐分钟**求解每个目标的可行观测区间，自动排出**互不重叠**的
观测序列，并保留**固定校准时段**不被占用；对未能安排的目标给出**首个冲突原因**。
时间线色块可直接**拖动调整**并即时重算，支持**保存版本**（SQLite）与**导出时间表 JSON**；
观测执行后还能对已保存版本做**实测曝光核验**，逐目标核算有效分钟是否达到原定曝光时长。

后端：Python + Flask + SQLite + NumPy（仅用于逐分钟向量运算）
前端：原生 HTML / CSS / JavaScript（SVG 时间线，零前端构建、零 CDN 依赖）

## 🧭 使用说明

### 1. 观测点与日期

- 纬度支持十进制或 `30.0N / 30.5S`；经度支持 `120.0E / 75.2W`。
- 日期按 **UTC** 解释，网格自动扩展为「开始日 00:00 UTC → 结束日次日 00:00 UTC」
  的逐分钟网格，天然处理**跨午夜**与多日边界。
- 规划范围上限 14 天（典型单晚计算 < 100 ms）。

### 2. 目标

| 字段 | 说明与示例 |
| --- | --- |
| 赤经 RA | `00h42m44s`、`18h36m56`（时分秒）；纯数字 ≤24 按小时、>24 按度数 |
| 赤纬 Dec | `41d16m09s`、`-20d52m` 或十进制 `-20.87` |
| 曝光时长 | 正整数分钟 |
| 优先级 | 整数，**数字越小越优先**；同级时曝光长的优先 |

### 3. 约束

- **夜间/暮光**：黑夜（太阳 < −18°）、天文晨昏蒙影（< −12°）、
  航海晨昏蒙影（< −6°）、民用晨昏蒙影（< 0°）。
- **最低高度**：目标地平高度必须 ≥ 该值。
- **最大空气质量**：平面平行大气模型 X = sec(z)；界面会提示其等效最低高度，
  两者取严格者生效。
- **固定校准时段**：强制保留，排程永远不会占用；校准之间不允许重叠（直接报错）。

### 4. 时间线

- 每条泳道是一个目标；背景分层颜色表示黑夜/三类暮光，绿色带为该目标的可行窗口，
  淡蓝曲线为目标高度曲线，金色块为锁定的校准时段。
- **拖动色块**整体平移观测时间；**拖动右缘**调整曝光时长。
  落点必须满足该目标的全部约束且不与任何时段重叠，否则提示原因并还原。
- 拖动确认后该目标变为「🟡 手动固定」，后续重算保持不动，其他目标围绕它重排；
  点击顶部「清除固定」可恢复全自动排程。
- 悬停色块可查看 UTC 时间、时长、优先级、全天最高高度与最佳空气质量。

### 5. 未安排目标的冲突归因

每个未安排目标都会给出**首个**冲突原因，例如：

- 「整个日期范围内最高高度仅 12.3°，始终低于最低高度 20°」
- 「高度达标，但全部处于白昼（当前要求太阳低于 −12°）」
- 「最长可行窗口仅 40 分钟，需要 60 分钟；暮光/白昼开始」
- 「首个可行窗口 10:55–20:59（604 分钟）被固定校准时段『黄昏平场』
  11:20–11:50 UTC 占用，剩余片段不足 45 分钟曝光」

### 6. 版本与导出

- **保存版本**：把当前输入与排程结果存入 SQLite，可随时载入或删除。
- **导出 JSON**：下载自描述文件 `observation-schedule-YYYY-MM-DD.json`，
  顶层结构为 `{schema, generated_at, request, schedule}`，便于与其他系统对接。

### 7. 实测曝光核验

观测执行后，可对照任一**已保存版本**核验实际曝光是否达标（页面左侧
「实测曝光核验」卡片）：

1. **选择版本**：下拉框列出全部已存版本，选定后提示该版本的日期范围与目标数。
2. **录入记录**：点「＋ 记录」逐条添加：目标（下拉选择，仅限版本内目标）、
   UTC 起止时间（精确到整分钟）。
3. 点「开始核验」，右侧结果表逐目标列出：
   **原定曝光时长、实测分钟、有效分钟、达标状态、被剔除区间及原因**。

核算规则（分钟一律**左闭右开** `[start, end)`，以版本保存的目标、可行窗口、
校准时段与排程为准）：

- 同一目标的多条记录取并集，**重叠部分只计一次** → 实测分钟；
- **不同目标实测相撞的部分从双方各扣除**；
- 再剔除**与固定校准重叠**、以及**落在自身可行窗口外**的分钟 → 有效分钟；
- 有效分钟 **≥ 原定曝光时长** 即为「✅ 完成」，否则显示差额。

偏离原排程但符合条件的实测同样计入；当初未排上的目标也可核验。
核验为**只读**操作，不会改动已保存的版本。
以下输入错误会**整批拒绝**（HTTP 400）：未知目标、非整分钟时间、
超出版本日期范围、起止倒置。

## 🔭 计算方法（球面天文）

1. **时间与恒星时**：UTC → 儒略日，USNO 多项式求 GMST，
   加经度得本地恒星时 LST（每平太阳分钟恒星时增量 360.9856…/1440 度）。
2. **太阳位置**：低精度太阳历书（平黄经 + 中心差 + 黄赤交角，Meeus），
   赤经赤纬每 5 分钟采样、分钟级前向填充。
3. **目标高度**：由时角 H = LST − RA 与赤纬 δ，
   `sin h = sin φ sin δ + cos φ cos δ cos H`，逐分钟求全网格。
4. **空气质量**：`X = sec z = 1 / cos(90° − h)`（高度 ≤ 0 记为 ∞）。
5. **可行窗口**：对「暮光阈值 ∧ 最低高度 ∧ 最大空气质量」逐分钟布尔掩码取连续段。
6. **排程**：按（优先级升序、曝光降序、输入顺序）贪心，
   在每个可行窗口中扣除已占用区间（含校准与手动固定时段），取第一个可容纳片段。
7. 忽略自行、章动与大气折射，太阳历书精度约 0.01°，对分钟级窗口规划足够。

## 🔌 HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/compute` | 提交输入，返回可行窗口、排程与冲突归因 |
| `POST` | `/api/export` | 同计算，返回带 `schema/generated_at` 的完整时间表 |
| `GET` | `/api/versions` | 版本列表 |
| `POST` | `/api/versions` | `{label?, request}` 保存版本（服务端重算） |
| `GET` | `/api/versions/<id>` | 取版本（含输入与结果） |
| `DELETE` | `/api/versions/<id>` | 删除版本 |
| `POST` | `/api/versions/<id>/verify` | 实测曝光核验（只读，见下） |
| `GET` | `/healthz` | 健康检查 |

请求示例：

```json
{
  "site": {"lat": "30.0", "lon": "120.0E"},
  "start_date": "2026-09-24",
  "end_date": "2026-09-25",
  "twilight_mode": "astronomical",
  "min_altitude": 20,
  "max_airmass": 2.5,
  "targets": [
    {"id": "m31", "name": "M31", "ra": "00h42m44s", "dec": "41d16m09s",
     "exposure_minutes": 45, "priority": 1}
  ],
  "calibrations": [
    {"id": "c1", "label": "黄昏平场",
     "start": "2026-09-24T11:20Z", "end": "2026-09-24T11:50Z"}
  ],
  "pins": {"m31": {"start_min": 1259}}
}
```

> `pins` 为可选的手动固定表：目标 id → 起始分钟（相对网格起点 00:00 UTC）；
> 非法固定（越界、离开可行窗口、与其他时段重叠）会被服务端拒绝并返回 warning。

#### 实测曝光核验 `POST /api/versions/<id>/verify`

请求体为若干条实际观测时段（UTC 整分钟起止，左闭右开）：

```json
{
  "records": [
    {"target_id": "m31", "start": "2026-09-24T12:10Z", "end": "2026-09-24T13:10Z"},
    {"target_id": "m31", "start": "2026-09-24T12:40Z", "end": "2026-09-24T13:30Z"},
    {"target_id": "vega", "start": "2026-09-24T13:00Z", "end": "2026-09-24T13:45Z"}
  ]
}
```

响应（节选）：`results` 覆盖版本内全部目标（未录入记录的目标 `record_count` 为 0），
`excluded` 逐段列出被剔除区间及原因：

```json
{
  "version_id": "…", "version_label": "…",
  "grid": {"start": "2026-09-24T00:00Z", "end": "2026-09-26T00:00Z"},
  "records_accepted": 3,
  "results": [
    {
      "target_id": "m31", "name": "M31",
      "planned_minutes": 45,
      "was_scheduled": true,
      "scheduled": {"start": "2026-09-24T12:05Z", "end": "2026-09-24T12:50Z"},
      "record_count": 2, "input_minutes": 110,
      "actual_minutes": 80, "effective_minutes": 65,
      "shortfall_minutes": 0, "complete": true,
      "records": [{"start": "…", "end": "…", "minutes": 60}],
      "excluded": [
        {"start": "2026-09-24T13:00Z", "end": "2026-09-24T13:30Z",
         "minutes": 30,
         "reason": "与其他目标实测时段相撞（Vega），双方均扣除"}
      ]
    }
  ],
  "summary": {"targets": 3, "verified": 2, "completed": 2}
}
```

错误：未知目标、非整分钟、超出版本日期范围、起止倒置等任一问题
都会使**整批**记录被拒绝（`400 {"error": "…"}`）；版本不存在返回 `404`。
核验不修改版本数据。
